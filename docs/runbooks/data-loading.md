# Green Rice DB Data Loading Runbook

Last updated: 2026-04-27

This runbook describes how to load the data required by the public Green Rice
DB pages. The Admin page is an operator surface for manually curated source
records, upload entry points, and readiness checks. Most large derived data
must be generated by scripts or server-side pipelines and then promoted to
Firestore / Firebase Storage.

## Preconditions

- Firebase project access for `green-rice-db`.
- `service-account.json` at the repository root for scripts that use
  Firebase Admin SDK.
- `functions-python/venv` set up for Python runbook commands invoked through
  npm.
- Admin user has the Firebase custom claim `admin`.
- Heavy Cactus / graph / VCF work should run on the analysis server, not in
  the browser Admin page.

## Operator Checkpoint

After each major stage, open `/admin` and check the **Data Readiness** panel.
The panel reports whether public pages have the Firestore documents and
Storage artifacts they need.

Readiness groups:

- **Source Records**: cultivar metadata and uploaded genome file sets.
- **Active Releases**: OrthoFinder, grouping, SV, and Discovery run versions.
- **Browse Indexes**: OG member chunks, gene index, gene models, functional
  index, trait-hit index, and gene-SV index.
- **Region And Discovery Artifacts**: SV matrix, OG region graph/AF bundles,
  and the active OG region pointer.

## Recommended Load Order

1. Load cultivar metadata.
2. Upload per-cultivar genome files.
3. Upload and process OrthoFinder results.
4. Build gene / OG browse indexes.
5. Build SV release artifacts.
6. Promote Discovery analysis results.
7. Build and promote OG region graph / AF artifacts.
8. Re-check `/admin` Data Readiness and public pages.

## 1. Cultivar Metadata

Use `/admin` to add or edit cultivar records.

Destination:

- Firestore `cultivars/{cultivarId}`

Used by:

- `/`
- `/cultivars`
- `/cultivar/:name`
- phenotype charts
- grouping / Discovery inputs

Notes:

- Writes to `cultivars/*` can trigger `on_cultivar_change`, which recomputes
  phenotype grouping and OrthoFinder diffs when the required upstream data is
  present.

## 2. Genome Files

Use either the Admin UI or the batch script.

Admin UI:

- `/admin` → edit cultivar → upload FASTA, gene GFF3, repeat output.

Batch upload:

```bash
npm run upload:genomes -- --input /path/to/cultivars_genomes
```

Explicit cultivar upload:

```bash
npm run upload:genomes -- --cultivar baegilmi \
  --fasta /data/baegilmi.fa \
  --gff /data/baegilmi.gff3 \
  --repeat /data/baegilmi.out
```

Destination:

- Storage `genomes/{cultivarId}/genome.fasta`
- Storage `genomes/{cultivarId}/gene.gff3`
- Storage `genomes/{cultivarId}/repeat.out`
- Firestore `cultivars/{cultivarId}.genomeSummary.files.*`

Used by:

- `/cultivar/:name`
- `/download`
- `/region/:cultivar/:chr/:range`

Known gap:

- Uploading files marks `genomeSummary.status = pending`. Confirm the
  genome-summary parsing workflow is available before treating the cultivar
  page as complete.

## 3. OrthoFinder Results

Use `/admin` → **OrthoFinder Results**.

Required files:

- `Orthogroups.GeneCount.tsv`
- `Orthogroups_with_description.tsv`

The Admin upload stages the files under `orthofinder/staging/{uploadId}/` and
calls the `start_orthofinder_processing` HTTPS function.

Generated destinations:

- Storage `orthofinder/v{N}/_matrix.json`
- Storage `orthofinder/v{N}/og-members/chunk_*.json`
- Storage `orthofinder/v{N}/og_descriptions.json`
- Storage `orthofinder/v{N}/baegilmi_gene_annotation.json`
- Firestore `_orthofinder_meta/state`
- Firestore `orthogroup_diffs/{traitId}` and payload paths

Used by:

- `/og`
- `/og/:ogId`
- `/pangenome`
- `/genes`
- `/discovery`

## 4. Gene / OG Browse Indexes

Run these after an active OrthoFinder version exists. Replace `6` with the
active version in `_orthofinder_meta/state`.

Gene-to-OG reverse index:

```bash
python3 scripts/build-gene-og-index.py --version 6
```

Gene models and functional annotation:

```bash
python3 scripts/build-gene-models.py \
  --funannotate-dir /10Gdata/ezy/02_Ongoing_Projects/00_Main/Green_Rice/results/funannotate_v2 \
  --version 6
```

Functional search index:

```bash
python3 scripts/build-functional-search-index.py --version 6
```

Trait-hit index:

```bash
python3 scripts/build-trait-hits-index.py
```

OG gene-coordinate index:

```bash
python3 scripts/build-gene-coords.py \
  --cultivar-gff-dir /path/to/results \
  --og-members-dir /path/to/og_members_chunks \
  --output /tmp/gene_coords_output
```

Generated destinations:

- Storage `gene_index/v{N}/_manifest.json`
- Storage `gene_index/v{N}/by_prefix/*.json`
- Storage `gene_models/v{N}/_manifest.json`
- Storage `gene_models/v{N}/by_prefix/*.json`
- Storage `functional_index/v{N}/index.json`
- Storage `trait_hits/v{orthofinderVersion}_g{groupingVersion}/index.json`
- Storage `og_gene_coords/chunk_*.json`

Used by:

- `/genes`
- `/genes/:geneId`
- `/og/:ogId`
- `/region/:cultivar/:chr/:range`
- `/pangenome`

Known gap:

- `orthofinder/v{N}/og_categories.json` is checked by Admin readiness and used
  by pangenome/OG category filters. The current classification helper is
  `scripts/classify-og-descriptions.sh`, but the final upload workflow should
  be explicitly runbooked before re-generating categories.

## 5. SV Release Artifacts

Build the canonical SV matrix from the Cactus pangenome VCF.

```bash
python3 scripts/build-sv-matrix.py --sv-version 1
```

Generated destinations:

- Firestore `sv_releases/sv_v1`
- Storage `sv_matrix/sv_v1/manifest.json`
- Storage `sv_matrix/sv_v1/events/by_chr/{chr}.json.gz`
- Storage `sv_matrix/sv_v1/group_freq/by_trait/{traitId}.json.gz`

Build cultivar-frame SV coordinate side tables:

```bash
python3 scripts/build-per-cultivar-sv-coords.py \
  --canonical-dir tmp/sv_matrix/sv_v1/events/by_chr \
  --sample-vcf-dir tmp/per_cultivar_vcfs
```

Build gene-SV overlap index:

```bash
python3 scripts/build-gene-sv-index.py \
  --canonical-dir tmp/sv_matrix/sv_v1/events/by_chr \
  --coord-dir tmp/sv_matrix/sv_v1/per_cultivar_coords \
  --gene-models-dir tmp/gene_models/v6/by_prefix \
  --of-version 6 \
  --sv-release-id sv_v1
```

Generated destinations:

- Storage `sv_matrix/sv_v1/per_cultivar_coords/{cultivar}/by_chr/{chr}.json.gz`
- Storage `gene_sv_index/v{orthofinderVersion}_rsv_v1/index.json`

Used by:

- `/sv`
- `/sv/:eventId`
- `/region/:cultivar/:chr/:range`
- `/genes`
- `/discovery/locus/:locusSlug`

## 6. Discovery Analysis Results

Run raw analysis on the analysis server or on a machine with the required raw
files and Python environment.

```bash
python3 scripts/run-raw-analysis.py --output /tmp/green_rice_raw_analysis
```

Promote to Firebase:

```bash
python3 scripts/promote-analysis-run.py \
  --run-dir /tmp/green_rice_raw_analysis \
  --dry-run

python3 scripts/promote-analysis-run.py \
  --run-dir /tmp/green_rice_raw_analysis
```

Generated destinations:

- Firestore `analysis_runs/{runId}`
- Firestore `analysis_runs/{runId}/candidates/{candidateId}`
- Firestore `analysis_runs/{runId}/blocks/{blockId}`
- Firestore `intersection_releases/{intersectionReleaseId}`
- Firestore `entity_analysis_index/{entityType}_{entityId}`
- Storage `analysis_runs/{runId}/step4_intersections.json.gz`
- Storage `analysis_runs/{runId}/blocks/{blockId}.json.gz`
- Storage `og_sv_intersections/{intersectionReleaseId}/by_og/{ogId}.json.gz`

Used by:

- `/discovery`
- `/discovery/locus/:locusSlug`
- `/og/:ogId`
- `/genes/:geneId`
- `/region/:cultivar/:chr/:range`

## 7. OG Region Graph / AF Release

This is the heaviest stage. Use the dedicated playbook:

- [`docs/runbooks/og-region-release.md`](./og-region-release.md)

Short form:

```bash
npm run prepare:og-region
# ship inputs and batch-region-extract.py to the analysis server
# run batch-region-extract.py remotely
# rsync og_region_graph and og_region_af back to local staging

npm run check:og-region-bundle /tmp/og_region_staging
npm run promote:og-region /tmp/og_region_staging
```

Generated destinations:

- Storage `og_region_graph/v{orthofinderVersion}_g{groupingVersion}/...`
- Storage `og_region_af/v{orthofinderVersion}_g{groupingVersion}/...`
- Storage `downloads/_og_region_manifest.json`

Used by:

- `/og/:ogId`
- `/region/:cultivar/:chr/:range`
- `/discovery/locus/:locusSlug`

## Final Verification

Run:

```bash
npm run lint
npm run type-check
npm run check:arch
npm run build
```

Then check:

- `/admin` Data Readiness has no unexpected `missing`, `partial`, or `error`
  rows.
- `/`
- `/cultivars`
- `/genes`
- `/og`
- `/pangenome`
- `/sv`
- `/discovery`
- `/download`

## Operating Principle

Do not manually edit large derived JSON artifacts from the Admin page. The
source of truth should be:

- Admin UI for curated source records and small source-file uploads.
- Scripts / server pipelines for derived indexes and release artifacts.
- `/admin` Data Readiness for release verification.
